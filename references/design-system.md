# 디자인 시스템 — 이스타항공 비즈니스 슬라이드

`assets/template.html`의 CSS 토큰과 이 문서의 값은 항상 같아야 한다. 값을 바꿀 때는 두 곳을 함께 고친다.

## 1. 캔버스

- 모든 슬라이드는 **1920×1080 고정 캔버스**다. 스크립트가 창 크기에 맞춰 `transform: scale()`로 확대·축소하므로, 이 문서의 px 값은 그대로 쓴다.
- 여백 128px. 안쪽 폭은 1664px, 높이는 824px이다.
- 푸터가 있는 본문 슬라이드는 아래 여백이 160px이다. 본문이 쓸 수 있는 높이는 792px이고, 푸터는 하단 64px 위치에 한 줄로 고정한다.
- 스크롤은 없다(`overflow:hidden`). 넘치면 글자를 줄이지 말고 **슬라이드를 나눈다.**

## 2. 색

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--navy` | `#0B1B2E` | 제목 글자, 표지·챕터·코드 패널 배경 |
| `--navy-2` | `#243449` | 어두운 배경 위 구분선 |
| `--bg` | `#F4F6F9` | 본문 슬라이드 배경 |
| `--bg-2` | `#EEF1F5` | 콜아웃, 표 머리글 |
| `--card` | `#FCFDFE` | 카드, 흐름 상자, 다이어그램 카드 |
| `--line` | `#D3DAE4` | 괘선 |
| `--ink-2` | `#475467` | 본문 글자 |
| `--ink-3` | `#5A6578` | 라벨, 각주, 푸터 |
| `--accent` | `#D51F29` | 이스타항공 메인 컬러 |
| `--accent-dark` | `#FF6B70` | 어두운 배경 위 강조(`#D51F29`는 남색 위에서 대비가 부족함) |
| `--on-dark` / `-2` / `-3` | `#F1F4F8` / `#A7B4C6` / `#8A97AA` | 어두운 배경 위 글자 |

강조색 규칙:

- 강조색은 **라벨(eyebrow, 콜아웃 라벨, 번호)과 슬라이드당 핵심 한 곳**에만 쓴다. 본문 문단을 빨갛게 칠하지 않는다.
- `#D51F29`를 흰 배경 위 글자로 쓸 때는 대비가 4.5:1 경계선이다. **굵게 24px 이상**으로만 쓴다.
- 전면 강조색 슬라이드(`.slide--statement`)는 덱에서 **한 장**만 쓴다.
- 색만으로 뜻을 전하지 않는다. 좋음/나쁨, 위험도는 글자로도 쓴다.
- 쓰지 않는 것: 그라디언트, 그림자, 왼쪽 색 막대가 달린 둥근 상자, 이모지, 파스텔 배경 박스.

## 3. 글꼴과 크기

| 역할 | 글꼴 | 크기 | 굵기 | 줄 간격 |
|---|---|---|---|---|
| 표지 제목, 강조 문장 | IBM Plex Sans KR | 120px | 600 | 1.1–1.15, 자간 −3px |
| 슬라이드 제목 | IBM Plex Sans KR | 64px | 600 | 1.2, 자간 −1px |
| 카드·흐름 제목 | IBM Plex Sans KR | 40px | 600 | 1.3 |
| 본문 | Noto Sans KR | 28px | 400 | 1.45–1.5 |
| 라벨, 표(조밀), 푸터 | Noto Sans KR | 24px | 600(라벨) | 1.4 |
| 코드, 경로, 버전 | JetBrains Mono | 24–64px | 400 | 1.2–1.6 |

- 크기는 이 다섯 단계만 쓴다. 강조는 새 크기가 아니라 굵기나 색으로 한다. 예외는 챕터 번호(320px, 굵기 200)뿐이다.
- **24px 미만 금지.** 24px에도 안 들어가면 내용이 너무 많은 것이다.
- 한글은 한 글자가 대략 글자 크기만큼 폭을 차지한다(28px이면 한 줄 1664px에 약 55자). 영문·숫자는 0.6배다.
- 문단 폭은 800–1200px로 제한한다. 1664px 전체 폭으로 문장을 늘어놓지 않는다.

## 4. 레이아웃 카탈로그

슬라이드마다 아래 중 하나를 고른다. 같은 종류의 슬라이드는 같은 마크업을 쓴다.

| 클래스 | 언제 | 용량 한도 |
|---|---|---|
| `.slide--dark.slide--cover` | 1번 슬라이드. 제목 + **결론 한 문단** + 메타(대상·버전·작성일) | 결론 3줄 |
| `.num-grid` | 요약: "할 일 세 가지" 같은 번호 목록 | 3칸, 설명 2줄 |
| `.rows` | 키-값 대응(무엇을 알고 싶으면 어디를 본다) | 4–5행 |
| `.slide--dark.slide--chapter` | 챕터 표지. 큰 번호 + 제목 + 다룰 내용 3개 | 항목 3개 |
| `.flow` + `.flow-note` | 선형 과정. 아래에 "그래서 무엇이 가능한가" 한 줄 | 4단계 |
| `.cards` | 구성 요소 세 개 비교. 핵심 하나만 `.card--key` | 3장 |
| `.steps` | 순서 있는 절차. 빠뜨리기 쉬운 단계만 `.step--key` | 6단계(3×2) |
| `.split` + `.code-panel` | 화면에 보이는 값, 버전, 경로를 크게 보여 주고 읽는 법 설명 | 설명 3개 |
| `table.data` | 기준·정상·조치처럼 여러 열을 비교 | 28px 5행 / `--compact`(26px) 7행 |
| `.diagram-card` | 분기·반복이 있는 흐름(Mermaid). 선형이면 `.flow`를 쓴다 | 노드 12개 |
| `.code-card` | 실제로 입력할 명령. highlight.js 적용 | 10줄 |
| `.slide--statement` | 반드시 기억할 경고·원칙 한 문장 | 덱당 1장 |
| `.compare` | 두 범주로 나누기(직접 할 일 / 넘길 일) | 칸당 4–5항목 |
| `.recap` | 마지막 요약: 상황 → 할 일 | 8칸 |
| `.refs` | 출처, 참고자료(항상 마지막 두 장) | 장당 8항목 |
| `.callout` | 슬라이드 아래쪽 보충 한 줄. 라벨은 "주의", "참고", "용어" 등 | 슬라이드당 1개 |

## 5. 구성 규칙

- **제목 위치 고정.** 본문 슬라이드의 `.head`는 항상 위쪽 여백에서 시작한다. 본문 슬라이드 전체를 세로 가운데 정렬하지 않는다(장마다 제목이 오르내린다). 세로 가운데 정렬은 강조 문장 슬라이드에만 쓴다.
- **아래를 비우지 않는다.** 본문이 짧으면 `.slide--spread`(위아래로 벌림)나 `.fill` 스페이서로 마지막 블록을 아래로 보낸다.
- **리듬.** 표지와 챕터는 남색, 본문은 밝은 회색, 강조 문장은 빨강 한 장이다.
- **글머리표 목록 대신 구조.** 나열은 표, 카드, 번호 단계, 키-값 행 중 하나로 바꾼다.
- **제목은 주제를 소개한다.** 한 덱 안에서 문장형이면 문장형, 명사형이면 명사형으로 통일한다. "X가 아니라 Y입니다" 같은 과장된 반전 제목을 쓰지 않는다.
- **없는 내용을 채우지 않는다.** 빈 공간을 메우려고 숫자, 아이콘, 문구를 지어내지 않는다. 확인하지 않은 수치는 `[__]`로 비워 둔다.

## 6. 넘기기 전 점검

- [ ] 1번 슬라이드에 결론이 있다.
- [ ] 모든 본문 슬라이드의 제목이 같은 높이에 있다.
- [ ] 24px 미만 글자가 없다. 넘치는 슬라이드는 나눴다.
- [ ] 강조색이 슬라이드당 한 곳을 넘지 않는다. 강조 문장 슬라이드는 한 장이다.
- [ ] 이모지, 그라디언트, 그림자, 왼쪽 색 막대 상자가 없다.
- [ ] Mermaid 카드마다 전체화면 버튼이 있고, 코드는 하이라이트된다.
- [ ] 마지막 두 장이 출처 → 참고자료 순서다.
- [ ] 하단 탐색 막대의 이전/다음 버튼과 번호 입력 이동이 동작하고, 새로고침해도 같은 장이 열린다.
